## 1. 产品战略

### 1.1 产品定位

Loka 是一个 **多AI Agent 协作平台**，让用户和 AI Agent 像同事一样协作完成各种知识工作。平台有两个核心：

- **Super Agent**：一套 Multi-Agent 系统，用户用自然语言下达任务，多个专业 Agent 并行工作交付结果。能力覆盖投资分析、市场调研、竞品研究、任务管理等场景。
- **Chats（人机协作社交）**：AI Agent 作为群组一等成员参与讨论和任务执行。不是 Bot 附属品，而是有名字、有记忆、有性格的协作伙伴。
- **Cash flow** ——简化、很容易使用、降低摩擦力
- **Payment** ——找场景、参考 tempo

**总结：** Loka 是一个你和 AI Agent 一起工作的地方——做投资分析、调研竞品、推进团队任务，全在一个平台里完成。

### 1.2 解决什么问题

| 场景 | 痛点 | Loka 的解法 |
|------|------|-------------|
| 投资分析 | 1. 渠道分散，信息来源很多<br>2. 没有好的判断策略<br>3. 涉及资金，对准确度要求更高 | 1. 信息聚合，专门负责不同渠道的数据采集<br>2. 多agent共识，提供更好的交易策略<br>3. 私有数据管道，准确性比通用agent更高——待定 |
| 人与AI的协作 | 1. 工具碎片化，研究用 Perplexity，讨论用 Telegram，任务管理用 Notion，AI 用 ChatGPT<br>2. Telegram / 微信群全靠人发言，缺乏agent的参与 | 1. 分析、讨论、任务在同一个平台，Agent 贯穿始终<br>2. 群里有 AI Agent 实时参与，@一下就能出分析、做总结、推进任务 |

**应用场景：**

**投研场景：**
- "调研xx公司背景，是否值得投资"
- "调研东南亚的外卖市场"
- "我想买xx美元的xx资产，评估投资风险"

**群聊场景：**
- a和b在群聊中讨论kyb的实现，@agent 可直接给出方案和推荐的第三方服务商
- A、b、c 进行了会议并分配任务，会议结束后agent自动发布总结并@对应成员负责的任务
- a创建了预测市场agent并总结下单策略，拉入粉丝进群围观跟单

### 1.3 产品特色

**特色一：Super Agent 不只做投资**

投资分析是 Super Agent 的核心能力之一，但它同样能做竞品调研、行业分析、项目尽调、任务拆解与跟踪。用户对它说"帮我调研一下东南亚的外卖市场"或者"帮我比较一下 Figma 和 Sketch 的优劣势"，它都能调度多个专业 Agent 并行工作，交付一份结构化的研究报告。

**特色二：AI Agent 是群成员，不是 Bot**

在 Loka 的群聊中，AI Agent 有独立的名字、性格、记忆。你在 A 群里让 Agent 分析过的内容，到 B 群里它还记得。这跟 Telegram Bot 的"无状态应答"完全不同。Agent 是你的同事，不是工具。

**特色三：从分析到协作的闭环**

Super Agent 生成的分析报告可以一键分享到群聊，群里的同事和 Agent 可以接着讨论、追问、推进下一步。分析不是孤立的个人行为，而是协作的起点。

### 1.4 竞争分析

| 竞品类型 | 代表 | 目标用户 | 它们的强项 | Loka 的差异 |
|----------|------|----------|-----------|-------------|
| 通用 AI | ChatGPT, Perplexity | 所有人 | 通用问答能力强 | 多agent协作+私有数据管道，在结果的准确性上更高 |
| AI 投研工具 | Surf AI, Genspark | 专业投资者、机构 | 垂类分析深度高 | 投资数据范围更广，自带群聊社交属性 |
| 投资社交 | Stocktwits, 雪球 | 散户 | UGC 社区活跃 | 内容全靠人工，信噪比低。Loka 通过 AI Agent 参与群聊注入专业分析能力，提升社区内容质量 |
| 人机协作 IM | Teamily | 企业团队 | AI 作为群成员概念领先 | Loka 以投资/研究分析切入，在垂直场景做更深 |
| 团队协作 | Slack, Notion | 企业团队 | 工作流成熟 | AI 作为有记忆能输出的成员，而不仅是辅助工具 |

**Loka 的位置：** 在 Teamily（人机协作）和 Surf AI（投资分析）之间，做一个"能深度分析也能协作执行"的 AI 原生平台。投资分析是切入点，但平台能力不止于此。

### 1.5 市场策略 (Go-to-Market)

#### 阶段一：冷启动——解决"初期没有用户"的问题

**核心思路：** 初期不依赖用户生成内容，而是用 AI 自动生产高质量内容抢占搜索和社交流量。

**1) AI 内容工厂**
- 用 Super Agent 批量生成当下热点的投资分析报告（如"英伟达 Q4 财报解读""Polymarket 大选预测市场分析"）。
- 将这些报告发布到 Twitter、LinkedIn、Medium、dev.to 等平台，署名 Loka，文末附平台链接。
- 报告质量必须高于市面上的通用 AI 输出（有图表、有数据引用、有结论），通过内容专业度建立品牌认知。
- **目标指标：** 每周产出 5-10 篇高质量分析报告，覆盖当周投资热点。

**2) 社交媒体矩阵运营**
- 建立 Loka 官方 Twitter 账号，日常发布 Super Agent 的分析片段（适合传播的截图/金句）。
- 在投资类话题（FinTwit、#investing、#stockmarket）下用专业观点互动，不做硬广，而是用分析质量吸引关注。
- 重点关注和互动 KOL（投资博主、分析师、科技评论人），争取被引用或转发。

**3) 种子用户直接触达**
- 在 Reddit（r/investing、r/stocks）、Discord 投资社区、ProductHunt 等平台发布产品，收集第一批种子用户。
- 提供内测邀请码机制，制造稀缺感。前 500 名注册用户永久解锁 Pro 功能。
- 直接私信 Twitter 上活跃的投资爱好者，邀请试用并给反馈。

**4) Founder 侧冷启动**
- 用 TrustMR API 预填充 Discover 页面，确保上线第一天就有内容可看，不出现空货架。
- 主动邀请 10-20 个种子 Founder 入驻，提供 "Listed on Loka" 认证徽章 + 免费 AI 分析报告作为激励。

#### 阶段二：增长期——内容飞轮 + 社交裂变

**1) 报告分享机制（产品驱动增长）**
- Super Agent 生成的 PDF 报告自带 Loka 品牌水印和平台链接。
- 用户分享报告到社交媒体 → 读者被报告质量吸引 → 点击链接注册使用 → 新用户生成自己的报告 → 继续分享。形成"内容即获客"的自然循环。

**2) 社交拉新**
- Chats 的群聊天然是拉新工具：用户想加朋友一起讨论，就得邀请对方注册。
- 信用分系统激励：邀请有效新用户 +30 分，500 分解锁高级功能，正向循环。

**3) SEO + 长内容沉淀**
- 将 AI 生成的高质量分析报告做成可被搜索引擎索引的公开页面。
- 用户搜索"XX 公司分析"或"XX 预测市场"时，Loka 的报告出现在搜索结果中，自然引流。

#### 阶段三：扩展期——从投资到通用协作

- 投资分析用户积累到一定量级后，逐步推出竞品调研、行业研究、团队任务协作等场景。
- 引入团队版（Team Plan），支持企业内多人 + Agent 协作工作空间。
- 建立 Agent 市场（Agent Marketplace），允许用户创建和分享自定义 Agent。

## 3. Super Agent

### 3.1 机制

Super Agent 会根据意图调动多个专业 Agent 并行工作，交付结构化结果。即：

```
用户输入任务 -> SuperAgent 判断需要调用的能力 -> 调用相应 Agent 能力 -> 组合答案，输出结果
```

### 3.2 Agent 路由

| 类型 | 任务 | 调用类型 | 输出 |
|------|------|----------|------|
| **通用类** | 简单通用对话，例如"hi" | 单agent的通用能力 | 通用回复 |
| **搜索类** | 搜索市场情绪，例如"了解市场对某个股票的看法" | Signal Radar | |
| | 搜索资产概况信息，例如"某只股票今天情况" | Daily Agent | |
| **分析类** | 深度分析某个资产背景信息、项目情况 | 投资分析 Agent | |
| | 某个资产投资建议 | 投资分析 Agent | |
| **模拟预测类** | 模拟巴菲特投资、给出投资建议 | AI Hedge Fund | |
| | 模拟预测市场 | | |
| **交易类（待定）** | 交易股票、crypto、polymarket资产 | | |

### 3.3 协作模式

- **Auto:** 自动路由，选择适合的模式
- **Fast:** 常规路由调用对应 Agent 能力
- **Roundtable:** 在调用 Agent 能力后，还要进行多 Agent 共识

### 3.4 资产类别

- 股票类
- Crypto 资产
- Polymarket

### 3.5 输出

#### a. 思考流

思考流为一个通用的模版，根据调用的 Agent 类型展示对应的模块，未调用就不显示。

**思考流 = 【搜索】+【分析】+【模拟】+【共识】+【完成】**

| 类型 | 调用 Agent | 思考流 |
|------|-----------|--------|
| **通用类** | | 不显示 |
| **搜索类** | Signal Radar | 【搜索】模块：显示搜索社媒平台 |
| | Daily Agent | 【搜索】模块：显示数据获取，从各个平台或服务商获取数据 |
| **分析类** | 投资分析 Agent | 【分析】模块显示：<br>1. 基本面分析<br>2. 技术分析<br>3. 舆情分析<br>4. 决策 |
| **模拟预测类** | AI Hedge Fund | 【模拟】模块：<br>构建模拟小组 → 各个模拟的 Agent 运行 → 输出预测结果 |
| **多 Agent 共识模式** | | 【共识】模块：<br>1. 构建共识小组<br>2. 进行讨论、直到达成共识<br>3. 共识结论 |

#### b. 输出结果

Super Agent 根据用户问题类型，自动路由到不同的输出模板。路由在 `evaluateRouting` 阶段完成，与思考流路由同步判断。

##### 路由决策树

按以下顺序依次判断，命中即停：

```
1. isSimpleChat === true？ → general
2. 问题是否明确提到知名投资大师名字，并要求从其视角/框架分析标的？
   → guru-council
   判据：出现"巴菲特/Buffett"、"达里奥/Dalio"、"林奇/Lynch"、
        "芒格/Munger"、"索罗斯/Soros"等大师名字，
        且搭配"视角/perspective"、"怎么看/会怎么分析"等意图词。
   注意：仅提到名字不算（如"巴菲特最近买了什么"→ research），
        必须是"用其投资框架来评估某标的"。
3. 问题是否关于具体可交易标的的买卖决策？
   → investment-analysis
   判据：问题围绕"值不值得买/卖"、"目标价"、"持仓建议"、
        "技术面走势"、"估值贵不贵"等交易导向问题，
        且涉及有明确 ticker 的公开交易资产。
4. 问题是否要求时效性市场概览/多资产行情速递？
   → market-brief
   判据：关键词含"今天/今日/本周/市场行情/wrap/涨跌/
        财报日历/要闻/板块轮动"，
        重点是"发生了什么"而非"深入分析某一个主题"。
5. 其余需要深度信息的问题 → research
   判据：行业调研、技术趋势、产业链、竞品对比、
        公司/项目背景调研（包括非上市公司）、
        封装产能/商业模式/市场格局等知识性深度问题。
```

优先级：guru-council > investment-analysis > market-brief > research > general

##### 关键区分维度

| 维度 | investment-analysis | research | market-brief | guru-council |
|------|-------------------|----------|-------------|-------------|
| 核心意图 | 做交易决策 | 获取深度认知 | 了解市场动态 | 多大师框架评估 |
| 标的类型 | 可交易（有 ticker） | 任意（含非上市） | 多资产/大盘 | 可交易（有 ticker） |
| 时间焦点 | 当前+前瞻 | 不限 | 今日/近期 | 当前+前瞻 |
| 产出预期 | 买/卖/持有建议 | 结论与见解 | 行情速递 | 多视角共识建议 |

##### 边界案例参考

| 问题 | queryType | 理由 |
|------|-----------|------|
| "NVDA 值得买吗" | investment-analysis | 交易决策导向，有 ticker |
| "台积电CoWoS封装产能分配是否向NVDA倾斜" | research | 产业链调研，不涉及买卖决策 |
| "Evaluate Midjourney as an investment — team, revenue, growth" | research | 非公开交易，VC 式尽调 |
| "今天美股怎么样" | market-brief | 时效性市场概览 |
| "NVDA 今天怎么走的" | investment-analysis | 关注具体标的价格走势 |
| "对比 Figma 和 Sketch" | research | 竞品分析，不涉及交易 |
| "今日加密市场要闻" | market-brief | 新闻速递，多资产概览 |
| "东南亚外卖市场调研" | research | 行业深度研究 |
| "从巴菲特和达里奥的视角分析NVDA" | guru-council | 明确要求大师框架评估标的 |
| "Analyze Tesla from Buffett's perspective" | guru-council | 同上 |
| "巴菲特最近买了什么股票" | research | 查大师动态，非用其框架分析 |
| "巴菲特的投资理念是什么" | research | 知识性问题，非评估标的 |
| "用价值投资的方法分析苹果" | investment-analysis | 提到方法论但未指名大师 |
| "Hi"、"你能干啥" | general | 问候/闲聊 |

##### 输出模板总览

| # | queryType | 输出结构 | Web 报告组件 |
|---|-----------|---------|-------------|
| 1 | `investment-analysis` | ① 行情摘要（Quote Snapshot）— 实时行情卡片 ② 执行摘要 — 偏向/操作/信心/关键触发 ③ 深度分析（2-4 节）— 基本面、估值、财务、技术面、宏观等 ④ 信号与噪声 — 市场高估 vs 低估的信号表格 ⑤ 持仓建议 — 入场/止损/目标价、仓位逻辑 ⑥ 压力测试 — 牛/基准/熊情景概率与价格影响 ⑦ 关注问题 — 前瞻性问题与数据触发点 | KPI 卡片网格、情景分析卡片、风险矩阵、专家观点、监控仪表盘、交易策略卡片 |
| 2 | `research` | ① 执行摘要 — 核心发现 + 结论 ② 背景与范围 — 研究对象的定义和边界 ③ 分析主体（3-5 节）— 市场规模、竞争格局、技术路线、产业链上下游、商业模式对比、团队背景、融资历史等 ④ 关键发现 — 可视化数据表格、对比矩阵 ⑤ 风险与挑战 ⑥ 结论与建议 ⑦ 关注问题 | ❌ 不生成 |
| 3 | `market-brief` | ① 市场概览 — 主要指数涨跌 + 整体情绪 ② 热点板块/资产 — 涨幅榜/跌幅榜 Top 5-10 ③ 关键催化剂 — 驱动今日行情的核心事件 ④ 财报/事件日历 — 今日已披露财报 + 市场反应 ⑤ 明日关注 — 即将发生的重要事件 | ❌ 不生成 |
| 4 | `guru-council` | ① 标的概览 — 基本信息 + 当前市场定位 ② 大师观点（每位 1 节）— 各大师的分析框架 + 对该标的的看法 + 信号/置信度 ③ 观点分歧 — 大师之间的核心分歧点 ④ 综合决策 — 加权共识结论 + 推荐操作 ⑤ 风险提示 | 大师头像卡片、观点对比矩阵、信心柱状图、共识仪表盘 |
| 5 | `general` | 无固定结构，直接文本回复。不生成目录、不生成 Web 报告、不套分析框架。 | ❌ 不生成 |

##### 双格式输出机制

对于 `investment-analysis`、`guru-council` 类型：

1. **Docs（Markdown）**— 先流式输出，用户即时可读
2. **Web（HTML）**— Markdown 完成后，后台异步生成对应类型的 HTML 报告
3. HTML 就绪后自动切换到 Web 视图，用户可通过 Docs/Web 标签随时切换
4. 两种视图下均保留行情卡片等通用组件

对于 `research`、`market-brief`、`general` 类型：仅输出 Markdown，不显示 Docs/Web 切换标签。

## 4. 社交网络 (Community)

### 4.1 定位

Chats 是 Loka 的第二卖点。核心差异是 AI Agent 作为群组一等成员，参考 Teamily 的"人机共存"模式。

**用户为什么用 Loka Community 而不用 Telegram / 微信 / Slack：**

| 能力 | Loka Community | 传统 IM（即使接了 Bot） |
|------|---------------|----------------------|

### 4.2 群类型

## 7. 订阅与配额系统

### 7.1 设计原则

参考 Perplexity 的「功能分区 × 次数限额」模型（详见 `docs/Super-Agent-Subscription-Research.md`）：

- **不使用 Credit 积分**。直接按 Super Agent 模式（Fast / Roundtable）分别计数，用户看到的是「Fast 还剩 8 次」而不是「还剩 500 积分」。
- **Auto 模式永远免费、不限次**，作为保底体验。
- **基础聊天（非 Agent 路由的日常对话）永远免费、不限次。**
- 付费用户购买的是"更高级模式的更多使用次数 + 优先响应速度"。

### 7.2 订阅计划

| 计划 | 月付 | 年付 | Fast 配额 | Roundtable 配额 | 重置周期 | 附加权益 |
|------|------|------|-----------|-----------------|----------|----------|
| **Free** | $0 | $0 | 20 次 | 3 次 | **每 7 天** | Unlimited casual chat |
| **Pro** | $49 | $489 (≈17% off) | 300 次 | 75 次 | **每 30 天** | Unlimited casual chat, Priority response speed |
| **Max** | $109 | $1087 (≈17% off) | 800 次 | 225 次 | **每 30 天** | Unlimited casual chat, Priority response speed, Early access to new features |

**关键说明：**
- **滚动周期重置**，不固定在周一或月初：
  - Free 用户：从**注册日**起每 7 天重置一次（如 4/20 注册 → 4/27 重置 → 5/4 重置…）
  - Pro / Max 用户：从**订阅激活日**起每 30 天重置一次
  - 用户可在 Settings 页面查看下次重置日期
- 年付享受约 17% 折扣。
- Auto 模式不消耗任何配额，所有计划均可无限使用。
- 支付方式：Visa / Mastercard / PayPal / USDC。

### 7.3 三种协作模式与配额关系

三种模式的**核心差异**在于是否调用 Agent 分析、以及调用几个 Agent：

| 模式 | 底层机制 | 说明 | 是否消耗配额 |
|------|----------|------|--------------|
| **Auto** | 直接模型对话，不经过 Agent | 用户的问题直接发给基础 LLM 对话，不调度任何专业 Agent 进行分析。响应最快，适合日常问答和轻度交互。 | ❌ 不消耗，永远可用 |
| **Fast** | 单 Agent 分析 | 根据用户意图路由到一个对应的专业 Agent（如 Signal Radar、投资分析 Agent、AI Hedge Fund 等）执行分析任务，输出结构化结果。单次调度，效率优先。 | ✅ 每次消耗 1 次 Fast 配额 |
| **Roundtable** | 多 Agent 共识分析 | 在 Fast 的基础上，额外召集多个专业 Agent 组成圆桌会议，进行多轮辩论与交叉验证，直到达成共识后输出最终报告。分析深度最高，消耗也最大。 | ✅ 每次消耗 1 次 Roundtable 配额 |

**简单类比：**
- Auto = 直接问 ChatGPT（快，但没有专业分析）
- Fast = 指派一位分析师帮你做报告
- Roundtable = 召集一个分析师小组开会讨论后给你结论

### 7.4 配额显示与交互规则

#### 7.4.1 模式选择器（Mode Selector）

模式选择器出现在两个位置：首页输入区下方（展开式）、聊天页输入区左侧（下拉式）。

**正常状态（有剩余配额）：**
- Fast / Roundtable 旁显示绿色标签 `X left`（如 `8 left`）
- 点击可正常切换模式

**配额耗尽状态（0 remaining）：**
- 标签变为灰色 `0 left`（`bg-gray-100 text-gray-400`）
- 该模式行整体变为半透明（`opacity-50`），鼠标变为禁止图标（`cursor-not-allowed`）
- **点击无效**，不可切换到该模式
- 用户被引导使用 Auto 模式（始终可用）或升级订阅

**Auto 模式：**
- 不显示配额标签
- 始终可选

#### 7.4.2 配额标签样式

| 状态 | 背景色 | 文字色 | 示例 |
|------|--------|--------|------|
| 有剩余 | `bg-green-50` | `text-green-600` | `8 left` |
| 已耗尽 | `bg-gray-100` | `text-gray-400` | `0 left` |

### 7.5 Upgrade 入口（按订阅档位分状态）

同样的位置根据当前用户的订阅档位（Free / Pro / Max）渲染不同的形态。核心原则：**已付费用户不应被当作"未付费"反复催促升级**，但仍保留可感知、不打扰的 upsell 入口。

**入口位置**：侧边栏用户区（3 处：移动抽屉 / 收起态 / 展开态）、首页右上角（桌面端）、聊天页 Header。

**按订阅档位的状态矩阵：**

| 档位 | 首页右上角 / 聊天页 Header | 侧边栏用户区 | 点击行为 |
|------|---------------------------|--------------|----------|
| **Free** | 主位按钮 `Upgrade Plan`（皇冠 + 描边呼吸动画 + 渐变文字） | 同上 | → Settings |
| **Pro** | 次级链接按钮 `Go Max →`（弱化样式，去掉呼吸动画，文字降为中性灰） | Plan 徽章 `Crown · Pro`（无呼吸动效，点击进入 Settings 查看用量 / 升级入口） | → Settings |
| **Max** | 不显示 CTA，改为展示 Plan 徽章 `Crown · Max`（金色） | 同上 | → Settings（查看用量，不再有升级文案） |

**视觉规范（Free 档 Upgrade 按钮 — 最强势）：**
- 边框：`border border-gray-300`，带呼吸动画（`upgrade-shimmer-outline`，在 `#e5e7eb` 和 `#d1d5db` 之间交替）
- 文字：渐变色（`linear-gradient(135deg, #f59e0b, #ef4444, #f59e0b)`），带平移动画
- 图标（皇冠 SVG）：`#e67e22`

**视觉规范（Pro 档 `Go Max →` — 次级）：**
- 边框：`border border-gray-200`，**无**呼吸动画
- 文字：`text-gray-600` 单色，`font-medium`（非渐变）
- 尺寸比 Free 档 Upgrade 按钮小一号
- 整体风格：承认用户已付费身份，不喊"升级"，仅提示下一档存在

**视觉规范（Plan 徽章 — Pro / Max 状态）：**
- Pro 徽章：`Crown(#6366f1)` + 文字 `Pro`（靛蓝色）
- Max 徽章：`Crown(#f59e0b)` + 文字 `Max`（金色），轻微光泽感（subtle shine）
- 形态：小圆角胶囊，`border border-gray-200 bg-white`
- 点击可进入 Settings（不作为主要操作，是附加信息展示）

**兜底逻辑：**
- 获取 `plan` 前（loading 或 API 失败）统一按 Free 渲染，避免已付费用户短暂看到错误状态
- 所有入口共用同一个 `plan` 状态源，避免首页 / 侧边栏不一致

### 7.6 Settings 页面（Plan 管理）

路径：侧边栏 → Settings，或点击任意 Upgrade 按钮跳转。

Settings 页面包含：

1. **当前用量概览**
   - Fast 使用进度条（如 `6 / 10 used`）
   - Roundtable 使用进度条（如 `1 / 2 used`）

2. **三个计划卡片并排**
   - 每个卡片展示：计划名、月付/年付价格、Fast/Roundtable 配额、附加权益列表
   - 当前计划标记为 `Current Plan`
   - **低于**当前档的计划显示 `Downgrade`（次级样式，或直接置灰"Included in your plan"）
   - **高于**当前档的计划显示 `Upgrade to Pro` / `Upgrade to Max` 按钮
   - 若用户已是 Max：只有"Current Plan"状态，不显示任何 Upgrade CTA

3. **付费周期切换**
   - Monthly / Annual 切换器，Annual 旁显示 `Save 17%` 标签

4. **支付方式**
   - 支持 Visa、Mastercard、PayPal、USDC

### 7.7 配额耗尽的完整用户流

当用户的某个模式配额降至 0 时：

```
用户发送消息（当前模式 = Fast，配额 = 0）
├─ 模式选择器中 Fast 显示灰色 "0 left"，不可点击
├─ 用户可切换到 Auto（免费，始终可用）继续使用
├─ 或点击 Upgrade 按钮 → 跳转 Settings 页面
│   └─ 查看当前用量 → 选择 Pro/Max → 完成支付 → 配额立即刷新
└─ 等待配额自然重置（Free: 每 7 天 / Pro|Max: 每 30 天，从注册/激活日起算）
```

**关键行为：**
- 配额耗尽**不会中断当前对话**，只是无法再以该模式发起新的查询
- Auto 模式作为保底，确保用户永远不会"完全用不了"
- 不弹出付费墙或强制中断，用温和引导而非硬拦截
